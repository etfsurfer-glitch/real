# 중개사 라운지 개편 — 엑셀형 고객 원장 설계안

작성 2026-08-05. 참고 프로토타입(고객 원장) + **엑셀 대체 전략** + **모바일 동등 원칙**. 구현 전 합의용.

---

## 0. 전제 두 가지

### 0-1. 우리 경쟁자는 CRM이 아니라 엑셀이다

중개사 대부분은 엑셀을 쓴다. "CRM이 없어서" 가 아니라 **엑셀이 실제로 잘 맞아서** 쓴다.
그걸 인정하지 않고 만든 CRM은 예쁘지만 안 쓰인다. 우리 라운지가 지금 그 상태다.

| | 엑셀 | 보통의 CRM |
|---|---|---|
| 입력 | 아무 칸에나 아무거나 친다 | 필수 항목·모달·유효성 검사 |
| 이동 | Tab·Enter·방향키, 손이 키보드를 안 떠남 | 마우스로 버튼 찾기 |
| 조망 | 한 화면에 50행이 보인다 | 카드 5개, 스크롤 |
| 대량 | 50행 붙여넣기 3초 | 한 건씩 등록 |
| 소유 | 파일이 내 것, 언제든 열림 | 남의 서버 |

**엑셀이 지는 지점** — 시트끼리 안 이어짐 / 아무도 안 알려줌 / 시세가 늙음 / 중복이 쌓임 /
인수인계 안 됨 / **폰에서 못 씀** / 파일 유출.

### 0-2. 데스크톱과 모바일은 같은 일을 하지 않는다

이게 이 문서의 두 번째 축이다. 모바일을 "작은 데스크톱"으로 보면 실패한다.

| | 데스크톱 | 모바일 |
|---|---|---|
| 장소 | 사무실 책상 | 차 안·현장·손님 앞·집 |
| 하는 일 | **정리·대량 입력·훑기** | **조회·즉시 기록·알림 대응** |
| 입력 단위 | 표 전체, 열 단위 | 한 줄, 한 건 |
| 손 | 두 손, 키보드 | 한 손, 엄지 |
| 약속 | "엑셀처럼 쓸 수 있다" | **"엑셀은 폰에서 아예 못 여는데 이건 열린다"** |

> 모바일에서 그리드를 억지로 재현하는 것은 답이 아니다.
> 모바일의 승부처는 **엑셀이 시도조차 못 하는 것**(전화 연동·즉시 기록·알림·오프라인)이다.

**원칙: 어떤 단계도 데스크톱만 내보내지 않는다.** 모바일 화면이 같이 나오지 않으면 그 단계는 미완이다.
"나중에 모바일" 로 미루면 영원히 안 온다.

## 1. 데스크톱 — 그리드가 중심

### 1-1. 반드시 되어야 하는 것 (안 되면 엑셀 사용자는 3분 만에 떠난다)

- **키보드 전용 조작** — 방향키, `Tab`/`Shift+Tab`, `Enter` 확정 후 아래, `Shift+Enter` 위,
  `F2`·더블클릭 편집, `Esc` 취소, `Delete` 비우기
- **타이핑 즉시 편집** — 셀을 고른 상태에서 글자를 치면 바로 입력 시작(엑셀 동작)
- **범위 선택** — `Shift+방향키`·드래그. 하단 상태바 `선택 12칸 · 합계 284억 · 평균 23.6억`
- **복사·붙여넣기** — 클립보드를 **TSV**로 주고받는다. 엑셀↔우리 그리드가 그대로 오간다
- **채우기 핸들** — 오른쪽 아래 모서리를 아래로 끌면 복제
- **되돌리기** — `Ctrl+Z`/`Ctrl+Shift+Z`. 셀 단위 로그 기반
- **열 고정·정렬·필터** — 고객·전화 두 열 고정, 헤더 클릭 정렬, 열별 필터
- **가상 스크롤** — 수천 행에서도 끊기지 않게

### 1-2. 한글 IME — 여기서 대부분의 그리드가 깨진다

한글 조합 중 `Enter`는 **조합 확정**이지 셀 이동이 아니다.
`compositionstart` ~ `compositionend` 구간에는 키 핸들러를 통째로 비활성화하고,
`compositionend` 이후의 `Enter`부터 이동으로 친다. **실기기(맥·윈도우·안드로이드·iOS) 실측 필수.**
놓치면 "이름 치다가 커서가 아래로 튄다" 가 되고, 그 순간 신뢰를 잃는다.

### 1-3. 구현 방식

- 후보: `react-data-grid`(MIT, DOM) / `glide-data-grid`(MIT, canvas)
- **DOM 기반 권장** — IME·접근성·기존 CSS 토큰 재사용이 canvas보다 훨씬 쉽다
- **그리드는 데스크톱 폭에서만 `lazy()` 로 로드한다.** 현재 메인 번들 2.1MB —
  폰에 그리드 코드를 내려보내면 LTE에서 첫 화면이 죽는다

## 2. 모바일 — 엑셀이 못 하던 것

### 2-1. 화면 구성

폰에서는 그리드를 **기본으로 쓰지 않는다.**

| 화면 | 내용 |
|---|---|
| **오늘** (첫 화면) | 오늘·내일 일정, D-3 이내 병목, 신규 상담·요청, 새 매칭 |
| **고객** | 카드 목록 + 검색. 카드 = 이름·유형칩·요건 요약 1줄·다음 액션·D-day |
| **고객 상세** | 요건 카드들 → 각 요건 펼치면 조건·매칭. 아래 고정바에 `전화 / 문자 / 메모 / 일정` |
| **표 보기**(선택) | 가로 스크롤 + 첫 열 고정, **읽기 전용**. 행을 탭하면 상세 시트 |

- 주요 동작은 **하단 고정바**(엄지 반경). 상단은 정보 표시만.
- 편집은 **바텀시트**로 뜬다. 전체 화면 폼으로 밀어내지 않는다(맥락을 잃는다).

### 2-2. 한 줄 입력 — 모바일의 주 입력 경로

폼 10칸을 폰에서 채우게 하면 아무도 안 쓴다. **한 줄로 친다.**

```
김철수 010-1234-5678 고덕동 84 24억까지 10월입주
   ↓ (즉시, 서버 왕복 없이)
이름 김철수 · 전화 010-1234-5678 · 지역 강동구 고덕동
전용 84㎡(34평) · 예산 ~24억 · 입주 2026-10        [이대로 저장] [고치기]
```

- **규칙 파서 우선.** 이름(한글 2~4자) / 전화(숫자 패턴) / 지역(동 사전) / 면적(`84`·`34평`) /
  금액(`24억`·`2억5천`) / 날짜(`10월`·`10/15`). **즉시 반응해야 한다** — 폰에서 3초 기다리면 안 쓴다.
- 규칙이 못 잡은 부분만 **AI 폴백**(있는 파서 재사용). 폴백은 선택이고, 없어도 저장은 된다.
- 못 잡은 나머지는 `raw_text` 에 **그대로 남는다.** 정리는 나중에 데스크톱에서.

> §3의 원문 열은 데스크톱 편의 기능이 아니라 **모바일 입력의 뼈대**다. 위상이 다르다.

- **음성 입력** — Web Speech API(한국어). 마이크 버튼 한 번, 말하면 같은 파서로 들어간다.
  현장에서 손이 안 빌 때 쓴다.

### 2-3. 전화가 트리거다 — 모바일 킬러 기능

통화 감지 사이드카(`design/biz_call_detect_설계안.md`, 미구현)와 결합한다.

- **수신 중** — "한구매님 · 구함 2건 · 병목: 전세보증금 반환 · 다음 액션: 반환일 확인"
- **통화 종료 직후** — "메모 한 줄" + `다음 액션 완료` 버튼. 여기서 안 남기면 영원히 안 남는다
- **모르는 번호** — "고객으로 저장할까요?" 한 번 탭

엑셀은 이걸 흉내조차 못 낸다. **모바일을 쓰는 이유 그 자체**가 된다.

### 2-4. 오프라인 — 데이터 모델에 영향을 준다

엘리베이터·지하주차장·현장에서 끊긴다. 이건 UI 문제가 아니라 **설계 문제**라 1단계부터 반영해야 한다.

- **조회 캐시**(IndexedDB) — 최근 본 고객 N명, 오늘·이번 주 일정, 내 매물장. PWA는 이미 있다
- **쓰기 큐** — 실패한 변경을 큐에 쌓고 온라인 복귀 시 재전송
- **멱등성 키** — 모든 쓰기 API가 클라이언트 생성 `client_uid` 를 받는다.
  재전송으로 같은 요건이 두 번 생기면 신뢰가 끝난다. **나중에 넣으면 API를 다 뒤집어야 한다**
- **충돌** — 서버 `updated_at` 비교. 다르면 조용히 덮지 말고 "다른 곳에서 바뀌었습니다" 를 보여준다
- 화면에 **동기화 상태**를 항상 표시(`저장됨` / `대기 3건` / `오프라인`). 조용한 실패가 최악이다

### 2-5. 알림

이미 있는 웹푸시(VAPID·TWA·iOS) 재사용. 새로 만들 게 없다.

- D-1 잔금·입주 / 병목 기한 임박 / 요건에 맞는 **새 급매 등장** / 새 상담·콕집요청
- 알림 탭 → 해당 고객 상세로 바로. 중간 단계를 두지 않는다

### 2-6. 태블릿

현장에서 손님에게 보여주는 화면. 그리드 **읽기**는 가능한 폭이다.
`641~1024px` 는 카드 2열 + 표 보기 허용, `1025px~` 부터 편집 그리드.

## 3. 자유 입력 — 원문 열 + 점진적 구조화

엑셀의 진짜 강점은 **아무거나 칠 수 있는 것**이다. 스키마를 강요하면 진다.

- 모든 요건 행에 **`원문` 열**. `강동구 고덕동 84 24~27억 10월입주` 라고 그냥 친다
- 시스템이 파싱해 **구조화 열을 제안**한다. 연한 배경 + 점선 밑줄, `Tab` 한 번이면 확정
- 구조화가 안 돼도 **행은 살아 있다.** 검색·정렬은 원문으로도 된다
- 데스크톱·모바일이 **같은 파서**를 쓴다(§2-2). 두 벌로 만들면 결과가 갈린다

### 사용자 정의 열

중개사는 자기 열을 만든다(`소개자`, `차량`, `애견동반`…).
`biz_needs.extra_json` 에 자유 키·값, 사무소별 열 정의는 `biz_sheet_columns`.
모바일 카드에는 **사용자가 고른 2개까지만** 노출(전부 보이면 카드가 무너진다).

## 4. 붙여넣기 = 도입 장벽의 90% (데스크톱)

중개사가 **지금 쓰는 엑셀을 그대로 붙여넣으면 원장이 채워져야** 한다.

1. 엑셀에서 범위 복사 → 그리드에 `Ctrl+V`
2. 헤더 자동 매핑 — `이름·성명·고객명`→고객, `연락처·전화·핸드폰·HP`→전화, `예산·금액·희망가`→예산 …
3. **매핑 확인 1회** — 틀린 것만 드롭다운으로 고친다
4. 중복 감지 — 이름+전화가 같으면 "3건이 기존 고객과 겹칩니다. 합칠까요 / 새로 넣을까요"

**함정**: 엑셀에서 전화번호를 숫자 서식으로 저장했으면 `01012345678` → `1012345678` 로 앞 0이
이미 날아가 있다. 감지해서 **물어보고** 복원한다(조용히 고치지 않는다).

모바일에는 붙여넣기를 넣지 않는다. 폰에서 표를 붙여넣는 사람은 없다.
대신 **파일 업로드**(카톡으로 받은 xlsx를 폰에서 열어 공유 → 우리 앱)는 열어 둔다.

## 5. 계산 열 — 엑셀이 못 만드는 열

사용자 입력 열과 **시각적으로 구분**한다(연회색 배경, 자물쇠, 편집 불가). 항상 최신.

| 계산 열 | 내용 | 근거 |
|---|---|---|
| **매칭** | 이 요건에 맞는 매물 N건 | 우리 매물장 → 전국 매물 → 급매 엔진 |
| **시세** | 같은 단지·평형 최근 실거래 / 현재 최저호가 | `transactions`, `listings_current` |
| **경쟁** | 광고 배율(매도 경쟁 강도) | 광고 vs 물건(Σ1/same_addr_cnt) |
| **D-day** | 다음 일정까지 남은 날 | `biz_events` |
| **준비상태** | 선행 조건 전부 완료 여부 | `biz_plan_conds` |
| **다음 액션** | 병목에서 파생 | 규칙 + 중개사가 덮어쓰기 가능 |
| **최근 연락** | 마지막 통화·문자·상담 | `biz_call_events`, 상담리드 |

- 데스크톱: 열로 보인다. 셀 클릭 → 오른쪽 패널에 매물 목록 → 콕집요청 제안으로 연결
- 모바일: 카드에 **매칭·D-day·다음 액션 세 개만** 띄운다. 나머지는 상세에서

## 6. 시트끼리 잇는다

```
고객 ──┬── 요건 (구함·내놓음)  ── 매칭 → 매물
       ├── 일정 (계약·중도금·잔금·입주·만기)
       └── 계약 (계약서 파싱)
```

- 요건 시트의 `고객` 열은 고객 시트를 참조하는 드롭다운 — **오타로 중복이 생기지 않는다**
- 계약서를 올리면 고객·요건·일정이 **동시에** 생긴다. 세 시트에 옮겨 적을 일이 없다
- 콕집요청이 들어오면 요건 행으로 **승격**된다(`biz_needs.src_request_id`)

## 7. 되돌아갈 길 — 내보내기

**언제든 xlsx/csv 전체 다운로드.** 화면 어딘가에 상시 노출.
"내 데이터가 갇힌다" 는 불안이 도입을 막는 가장 큰 심리 장벽이다.
나갈 문을 크게 열어 두면 오히려 들어온다.

```
biz_plan_conds       선행 조건   id, customer_id, title, status(미정|진행|완료),
                                 gate(계약 전|잔금 전|입주 전), amount, expected_date, memo
biz_plan_links       연결(다대다) from_kind(base|cond), from_id, to_kind(cond|need), to_id

biz_sheet_columns    사무소별 열 정의  realtor_id, key, label, type, width, order, hidden, mobile_show
biz_cell_log         셀 변경 이력      table, row_id, col, before, after, user_id, at
                                       -- 되돌리기 + 직원 여러 명일 때 "누가 바꿨나"
```

★ 표시가 **모바일 때문에 1단계부터 들어가야 하는 것**이다. 나중에 넣으면 API를 전부 뒤집는다.

`biz_plan_links` 를 다대다로 두는 이유: 프로토타입에서도 선행 조건 2개가 목표 2개에 **교차로** 걸린다
(전세보증금 반환 → 매매·전세 양쪽, 대출 한도 → 양쪽). 1:N 이면 그 그림을 못 그린다.

### 파생값은 저장하지 않는다

병목 = 미완료 선행 조건 중 `gate` 가 이르고 `expected_date` 가 빠른 것. 준비상태·다음 액션도 여기서 계산.
**저장하면 반드시 어긋난다** — 조건을 바꿨는데 상태가 그대로면 화면 전체를 못 믿게 된다.

### 저장·동기화

- 셀/필드 편집 → 즉시 `PATCH`(낙관적 반영). 실패 시 빨간 테두리 + 재시도 큐
- 모든 쓰기는 `client_uid` 멱등. 같은 uid 재전송은 갱신이지 생성이 아니다
- 충돌은 **last-write-wins + 변경 표시**. 실시간 동시편집(CRDT)은 이 규모에 과하다

## 9. 뷰 전환 — 같은 데이터, 네 얼굴

| 뷰 | 데스크톱 | 모바일 |
|---|---|---|
| **그리드** | 기본 | 읽기 전용 표 보기(선택) |
| **원장 펼침** | 거래 계획 곡선 플로우(SVG) | 세로 3단 스택(기반→조건→목표) |
| **캘린더** | 월 그리드 + 목록 | 주간 스트립 + 목록 |
| **보드** | 상태별 칼럼(탐색→비교→협상→계약) | 상태 필터 칩 + 카드 |

곡선 커넥터는 좁은 화면에서 읽히지 않는다. **모바일에서는 버린다** — 축소해서 넣지 않는다.

## 10. 정보 구조(IA)

```
영업     고객 원장 · 콕집요청 · 상담신청
매물     매물장 · 매물점검
거래     계약관리 · 계약캘린더
사무소   홈페이지 · 직원관리 · 내 사무소 · 정보수정
```

- 데스크톱: 좌측 레일 + 그룹. 대시보드는 최상단 고정
- 모바일(비즈앱): 하단 탭 **4개로 고정** — `오늘 · 고객 · 매물 · 더보기`.
  나머지는 전부 `더보기` 안으로. 탭이 5개를 넘으면 엄지로 못 누른다

## 11. 단계 — 각 단계는 데스크톱+모바일이 함께 나온다

| 단계 | 데스크톱 | 모바일 | 이 단계로 얻는 것 |
|---|---|---|---|
| **0** | 대시보드 2단(현황+일정) | — | **완료 2026-08-05** |
| **1** | `biz_needs`(★필드 포함) + 그리드 **읽기** | 고객 카드 목록 + 상세 | 요건이 한 화면에 보인다 |
| **2** | **셀 편집·키보드·IME·붙여넣기·내보내기** | **한 줄 입력 + 규칙 파서** | **엑셀에서 이사 온다** |
| **3** | 계산 열(매칭·시세·D-day·최근 연락) | 카드에 매칭·D-day·다음 액션 | 엑셀로 못 돌아간다 |
| **4** | 오프라인 캐시·쓰기 큐·동기화 표시 | 같음(여기가 주 무대) | 현장에서 끊겨도 쓴다 |
| **5** | 원문 AI 파싱 제안 + 사용자 정의 열 | 음성 입력 | 입력이 빨라진다 |
| **6** | 거래 계획 곡선 플로우 + 병목·다음 액션 | 세로 3단 스택 | 프로토타입 화면 완성 |
| **7** | 캘린더 양방향 + 병목 알림 | 웹푸시 + 통화 트리거 | 손 안 대도 굴러간다 |
| **8** | 보드 뷰 · 좌측 레일 IA | 하단 탭 4개 재편 | 마무리 |

**2단계가 승부처다.** 1단계는 준비, 3단계는 잠금.
2단계 없이 3단계로 뛰면 "예쁜데 입력을 못 하는" 지금 상태가 반복된다.

**4단계(오프라인)를 뒤로 못 미루는 이유**는 §8의 ★ 필드 때문이다. 스키마는 1단계에 넣고
동작만 4단계에서 켠다. 반대로 하면 API를 다시 짠다.

## 12. 위험과 함정

| 위험 | 대응 |
|---|---|
| 한글 IME에서 커서가 튄다 | `composition` 구간 키 핸들러 차단, 실기기 4종 실측 |
| 전화번호 앞 0 소실 | 붙여넣기 시 감지 후 **물어보고** 복원 |
| 폰에서 첫 화면이 안 뜬다 | 그리드는 데스크톱 폭에서만 `lazy()`. 모바일 번들 예산을 정해 CI에서 감시 |
| 오프라인 재전송으로 중복 생성 | `client_uid` 멱등 — **1단계부터** |
| 저장 실패를 모른 채 계속 입력 | 실패 셀 표시 + 상단 배너 + 동기화 상태 상시 노출 |
| 동시 편집 충돌 | `updated_at` 비교, "○○님이 방금 바꿨습니다" |
| 개인정보 노출 | 한 화면에 전화번호 수백 개 — 직원 권한(owner/staff) 분리, 열람 로그, 마스킹 토글. **분실 위험이 큰 폰에서 더 중요** |
| 한 줄 파서가 자꾸 틀린다 | 규칙 우선·즉시 반영, 실패해도 `raw_text` 로 저장은 성공. **저장을 막지 않는다** |
| 만들어도 안 쓴다 | 2단계 완료 시점에 실제 중개사 3명에게 **자기 엑셀을 붙여넣게** 하고, **폰으로 하루 써보게** 한 뒤 결정 |

## 13. 먼저 정해야 할 것

1. **개방 시점** — `/biz/*` 는 전부 관리자 가오픈이다. 법률 준수 메모상 **중개사 약관 동의 게이트가
   캘린더·고객원장 개방의 선행 조건**이다. 만들되 게이트 뒤에 둘지, 게이트를 먼저 칠지.
2. **실제 엑셀 확보** — 지금 쓰는 엑셀 5~10개를 봐야 열 매핑 사전과 한 줄 파서 규칙을 만든다.
   **가장 먼저 필요한 것.** 이게 없으면 2단계 전체가 추측이 된다.
3. **모바일 우선순위** — 통화 트리거(§2-3)는 네이티브 사이드카가 필요하다(미구현).
   7단계까지 미룰지, 앞당겨 모바일 킬러 기능을 먼저 확보할지.
4. **역할 용어** — `주안 / 대안 / 보유` 를 현장 용어 그대로 쓸지.
5. **선행 조건 프리셋** — 전세보증금 반환·주담대 한도·기존 주택 매도·전입 가능일 등 실제 목록.
6. **범위** — 3단계까지를 1차로 볼지, 6단계(거래 계획)까지 한 묶음으로 볼지.
