# 중개사 라운지 개편 — 엑셀형 고객 원장 설계안

작성 2026-08-05. 참고 프로토타입(고객 원장) + **엑셀 대체 전략** + **모바일 동등 원칙**. 구현 전 합의용.

---

## 0. 전제 두 가지

### 0-1. 우리 경쟁자는 CRM이 아니라 엑셀이다

중개사 대부분은 엑셀을 쓴다. "CRM이 없어서" 가 아니라 **엑셀이 실제로 잘 맞아서** 쓴다.
그걸 인정하지 않고 만든 CRM은 예쁘지만 안 쓰인다. 우리 라운지가 지금 그 상태다.

| | 엑셀 | 보통의 CRM |
|---|---|---|
| 입력 | 아무 칸에나 아무거나 친다 | 필수 항목·모달·유효성 검사 |
| 이동 | Tab·Enter·방향키, 손이 키보드를 안 떠남 | 마우스로 버튼 찾기 |
| 조망 | 한 화면에 50행이 보인다 | 카드 5개, 스크롤 |
| 대량 | 50행 붙여넣기 3초 | 한 건씩 등록 |
| 소유 | 파일이 내 것, 언제든 열림 | 남의 서버 |

**엑셀이 지는 지점** — 시트끼리 안 이어짐 / 아무도 안 알려줌 / 시세가 늙음 / 중복이 쌓임 /
인수인계 안 됨 / **폰에서 못 씀** / 파일 유출.

### 0-2. 데스크톱과 모바일은 같은 일을 하지 않는다

이게 이 문서의 두 번째 축이다. 모바일을 "작은 데스크톱"으로 보면 실패한다.

| | 데스크톱 | 모바일 |
|---|---|---|
| 장소 | 사무실 책상 | 차 안·현장·손님 앞·집 |
| 하는 일 | **정리·대량 입력·훑기** | **조회·즉시 기록·알림 대응** |
| 입력 단위 | 표 전체, 열 단위 | 한 줄, 한 건 |
| 손 | 두 손, 키보드 | 한 손, 엄지 |
| 약속 | "엑셀처럼 쓸 수 있다" | **"엑셀은 폰에서 아예 못 여는데 이건 열린다"** |

> 모바일에서 그리드를 억지로 재현하는 것은 답이 아니다.
> 모바일의 승부처는 **엑셀이 시도조차 못 하는 것**(전화 연동·즉시 기록·알림·오프라인)이다.

**원칙: 어떤 단계도 데스크톱만 내보내지 않는다.** 모바일 화면이 같이 나오지 않으면 그 단계는 미완이다.
"나중에 모바일" 로 미루면 영원히 안 온다.

## 1. 데스크톱 — 그리드가 중심

### 1-1. 반드시 되어야 하는 것 (안 되면 엑셀 사용자는 3분 만에 떠난다)

- **키보드 전용 조작** — 방향키, `Tab`/`Shift+Tab`, `Enter` 확정 후 아래, `Shift+Enter` 위,
  `F2`·더블클릭 편집, `Esc` 취소, `Delete` 비우기
- **타이핑 즉시 편집** — 셀을 고른 상태에서 글자를 치면 바로 입력 시작(엑셀 동작)
- **범위 선택** — `Shift+방향키`·드래그. 하단 상태바 `선택 12칸 · 합계 284억 · 평균 23.6억`
- **복사·붙여넣기** — 클립보드를 **TSV**로 주고받는다. 엑셀↔우리 그리드가 그대로 오간다
- **채우기 핸들** — 오른쪽 아래 모서리를 아래로 끌면 복제
- **되돌리기** — `Ctrl+Z`/`Ctrl+Shift+Z`. 셀 단위 로그 기반
- **열 고정·정렬·필터** — 고객·전화 두 열 고정, 헤더 클릭 정렬, 열별 필터
- **가상 스크롤** — 수천 행에서도 끊기지 않게

### 1-2. 한글 IME — 여기서 대부분의 그리드가 깨진다

한글 조합 중 `Enter`는 **조합 확정**이지 셀 이동이 아니다.
`compositionstart` ~ `compositionend` 구간에는 키 핸들러를 통째로 비활성화하고,
`compositionend` 이후의 `Enter`부터 이동으로 친다. **실기기(맥·윈도우·안드로이드·iOS) 실측 필수.**
놓치면 "이름 치다가 커서가 아래로 튄다" 가 되고, 그 순간 신뢰를 잃는다.

### 1-3. 구현 방식

- 후보: `react-data-grid`(MIT, DOM) / `glide-data-grid`(MIT, canvas)
- **DOM 기반 권장** — IME·접근성·기존 CSS 토큰 재사용이 canvas보다 훨씬 쉽다
- **그리드는 데스크톱 폭에서만 `lazy()` 로 로드한다.** 현재 메인 번들 2.1MB —
  폰에 그리드 코드를 내려보내면 LTE에서 첫 화면이 죽는다

## 2. 모바일 — 엑셀이 못 하던 것

### 2-1. 화면 구성

폰에서는 그리드를 **기본으로 쓰지 않는다.**

| 화면 | 내용 |
|---|---|
| **오늘** (첫 화면) | 오늘·내일 일정, D-3 이내 병목, 신규 상담·요청, 새 매칭 |
| **고객** | 카드 목록 + 검색. 카드 = 이름·유형칩·요건 요약 1줄·다음 액션·D-day |
| **고객 상세** | 요건 카드들 → 각 요건 펼치면 조건·매칭. 아래 고정바에 `전화 / 문자 / 메모 / 일정` |
| **표 보기**(선택) | 가로 스크롤 + 첫 열 고정, **읽기 전용**. 행을 탭하면 상세 시트 |

- 주요 동작은 **하단 고정바**(엄지 반경). 상단은 정보 표시만.
- 편집은 **바텀시트**로 뜬다. 전체 화면 폼으로 밀어내지 않는다(맥락을 잃는다).

### 2-2. 한 줄 입력 — 모바일의 주 입력 경로

폼 10칸을 폰에서 채우게 하면 아무도 안 쓴다. **한 줄로 친다.**

```
김철수 010-1234-5678 고덕동 84 24억까지 10월입주
   ↓ (즉시, 서버 왕복 없이)
이름 김철수 · 전화 010-1234-5678 · 지역 강동구 고덕동
전용 84㎡(34평) · 예산 ~24억 · 입주 2026-10        [이대로 저장] [고치기]
```

- **규칙 파서 우선.** 이름(한글 2~4자) / 전화(숫자 패턴) / 지역(동 사전) / 면적(`84`·`34평`) /
  금액(`24억`·`2억5천`) / 날짜(`10월`·`10/15`). **즉시 반응해야 한다** — 폰에서 3초 기다리면 안 쓴다.
- 규칙이 못 잡은 부분만 **AI 폴백**(있는 파서 재사용). 폴백은 선택이고, 없어도 저장은 된다.
- 못 잡은 나머지는 `raw_text` 에 **그대로 남는다.** 정리는 나중에 데스크톱에서.

> §3의 원문 열은 데스크톱 편의 기능이 아니라 **모바일 입력의 뼈대**다. 위상이 다르다.

- **음성 입력** — 마이크 버튼 한 번. 방식과 실측 결과는 아래 2-2-1.

### 2-2-1. 음성 메모 → 자동 기입 (실측 완료 2026-08-05)

말로 남기면 텍스트로 옮겨지고 필드까지 채워지는가 — **된다.** 실기기 대신 합성음성으로 검증했다.

**방식: Web Speech API가 아니라 Gemini 오디오 직접 입력.**
브라우저 STT는 무료지만 단지명·금액 표현에 약하고 iOS 지원이 들쭉날쭉하다.
Gemini는 **받아쓰기와 구조화를 한 번에** 한다. 이미 키·클라이언트·파싱 프롬프트가 다 있어 새로 붙일 게 없다.

**실측 1 — 형식.** `MediaRecorder` 가 만드는 **webm/opus 를 변환 없이 그대로 받는다.**
webm·ogg·wav·mp3 모두 통과(각 3.0~3.1초). 서버에 ffmpeg 를 두거나 클라이언트에서 트랜스코딩할 필요가 없다.

**실측 2 — 정확도.** 15초짜리 통화 메모 한 건:

> "김철수 사장님 통화했고요, 고덕동 래미안힐스테이트 84제곱 24억까지 보시고 10월 입주 원하십니다.
> 전세보증금 9억 반환이 안 되면 어렵다고 하시네요."

`gemini-2.5-flash` 결과 — 고객명 `김철수` · 지역 `고덕동` · 단지 `래미안 힐스테이트` ·
전용 `84㎡` · 예산 `2,400,000,000` · 입주 `10월` ·
**선행조건 `전세 보증금 반환 / 9억`** 까지 전부 맞혔다.
말 한 번에 §8의 `biz_plan_conds` 한 행이 생긴다는 뜻이다.

**실측 3 — 모델.** `flash-lite` 는 단지명을 `내미안` 으로 잘못 듣고 원문 필드를 비웠다.
**여기서는 `flash` 를 쓴다.** (AI 상담은 lite 유지 — 용도가 다르다.)

**실측 4 — 함정. 무음·잡음에서 프롬프트를 그대로 되뱉는다.**
6초 무음과 핑크노이즈를 넣었더니 응답이 **지시문 전문 그대로**였다.
그냥 `resp.text` 를 메모에 넣었으면 손님 메모에 우리 프롬프트가 박힌다.

> **대응: 자유 텍스트로 받지 않는다.** `response_schema` 에 `들림(boolean)` 을 두고 JSON 으로 강제한다.
> 무음·잡음 `들림=false`, 웅얼거림·정상 발화 `들림=true` — **4/4 정확.** 되뱉기가 완전히 사라졌다.
> 추가로 업로드 전 클라이언트에서 RMS 레벨을 재 무음이면 아예 보내지 않는다(비용·지연 0).

**실측 5 — 단지명 교정(우리만 되는 것).** STT 의 최대 약점이 고유명사다.
받아쓴 `래미안 힐스테이트` 를 지역 코드로 좁혀 우리 단지 DB 에 조회하니
**`고덕래미안힐스테이트`(108187) 로 정정**됐다. `고덕 그라시움` → `고덕그라시움` 도 동일.
다만 한 글자가 틀린 `내미안 힐스테이트` 는 LIKE 로 못 잡는다 → **자모 분해 유사도 폴백**이 필요하다.

**비용 — 실측 토큰 × 공시 단가 (2026-08-05 확인)**

토큰은 **오디오 1초당 정확히 32토큰**으로 선형이다(10초 354 / 30초 994 / 60초 1,954 — 프롬프트 34토큰 포함).
`gemini-2.5-flash` 유료 단가: 오디오 입력 $1.00 · 텍스트 입력 $0.30 · 출력 $2.50 (각 100만 토큰).

| 메모 길이 | 오디오 입력 | 출력 | 건당 | 원화(1,400원/$ 가정) |
|---|---|---|---|---|
| 10초 | 320토큰 $0.00032 | 146토큰 $0.00037 | **$0.00070** | **약 1.0원** |
| **30초(기준)** | 960토큰 $0.00096 | 300토큰 $0.00075 | **$0.00172** | **약 2.4원** |
| 60초(상한) | 1,920토큰 $0.00192 | 477토큰 $0.00119 | **$0.00312** | **약 4.4원** |

**규모별 월 비용** (30초 평균 2.4원 · 30일)

| 중개사 | 1인 하루 메모 | 월 건수 | 월 비용 |
|---|---|---|---|
| 10명 | 10건 | 3,000 | **7,200원** |
| 100명 | 10건 | 30,000 | **7.2만원** |
| 500명 | 10건 | 150,000 | **36만원** |
| 1,000명 | 10건 | 300,000 | **72만원** |
| 1,000명 | 30건(헤비) | 900,000 | **216만원** |

**비교 기준**

- 알리고 SMS 1건 ≈ 20원 → **음성 메모는 문자 한 통의 1/8**
- 우리 AI 상담 1건 ≈ 3.4원(실측 입력 22,448 · 출력 416토큰, flash-lite 단가)
  → **음성 메모(2.4원)가 이미 무료로 푸는 AI 상담보다 싸다**
- 중개사 한 명이 한 달에 300건을 남겨도 **720원**

**비용 구조에서 주의할 점 — 출력이 오디오보다 비싸다.**
30초 기준 출력이 건당 비용의 **44%** 다. 출력 단가($2.50)가 오디오 입력($1.00)의 2.5배이기 때문이다.
받아쓴 원문을 돌려받는 건 꼭 필요하니 줄일 수 없지만, **스키마에 안 쓸 필드를 넣으면 그대로 돈이 샌다.**
필드는 실제로 화면에 쓰는 것만 둔다.

**flash-lite 로 내리면?** 30초 0.57원으로 4.2배 싸다. 하지만 실측에서 단지명을 틀렸다(§실측 3).
**월 72만원을 17만원으로 줄이자고 단지명을 틀리는 건 손해다.** `flash` 고정.

**공짜로 줄이는 방법** — 업로드 전 RMS 게이트로 무음은 아예 안 보낸다(그 건 0원).
녹음 60초 상한으로 최악을 4.4원에 묶는다.

**숨은 비용.** 30초 opus ≈ 100KB. 월 30만 건이면 **업로드 30GB + Gemini 전송 30GB**.
API 키 때문에 클라이언트→Gemini 직접 호출은 불가하므로 반드시 우리 박스를 경유한다.
2코어 박스에서 출퇴근 피크 동시 업로드를 감당하는지 확인이 필요하다(비용보다 이쪽이 병목).

**지연.** 10초 3.8s · 30초 3.7s · 60초 5.5s.

### 2-2-2. AI 없이 되는 부분은 어디까지인가 (실측 2026-08-05)

**음성 → 텍스트는 AI 없이 불가능하다.** 음성인식 자체가 AI다.
브라우저 `SpeechRecognition` 도 뒤에서 구글 AI 가 돈다 — 다른 건 **우리가 돈을 안 낸다**는 것뿐이고,
음성이 밖으로 나가는 건 똑같다(개인정보 관점에서 Gemini 와 차이가 없다).

**텍스트 → 필드(구조화)는 규칙만으로 상당 부분 된다.** 순수 정규식 파서를 만들어 5개 문장에 돌렸다.

| 잘 되는 것 | 결과 |
|---|---|
| 아라비아 숫자 금액 | `24억` → 2,400,000,000 |
| **한글 수사** | `이십사억`→24억 · `팔십사제곱`→84㎡ · `시월`→10월 · `구억`→9억 |
| 면적 환산 | `34평` → 112.4㎡ |
| 전화번호 | `010-1234-5678` → 01012345678 |
| 이름 | `김철수 사장님` → 김철수 |
| 구두점 없는 문장 | 브라우저 STT 출력에서도 동일하게 동작 |

**규칙이 틀리는 것 — 전부 문맥 판단이다**

1. **거래유형을 오판한다.** "고덕동 84 **24억**까지 보시고 … **전세**보증금 9억 반환이 안 되면"
   → 규칙은 `전세` 라는 낱말만 보고 **B1(전세)** 로 찍는다. 실제로는 **매매를 찾는 손님**이고
   전세는 현재 거주 상태다. **틀린 값이 조용히 들어간다 — 이게 규칙만 쓰면 안 되는 이유다.**
2. **금액의 역할을 모른다.** 24억(예산)과 9억(보증금)이 같이 나오면 규칙은 둘을 구분할 수 없다.
   "가장 큰 값이 예산" 같은 편법은 "9억 보증금 받으면 24억까지" 문장에서 우연히 맞을 뿐이다.
3. **의미 단위를 못 잡는다.** `전세 보증금 9억 반환` 에서 금액이 가운데 끼어 있어
   '보증금 반환' 이라는 **선행 조건**을 낱말 매칭으로는 못 뽑는다. Gemini 는 뽑았다.

> 정리: **숫자는 규칙, 문맥은 AI.**

**온디바이스·자체 호스팅은?**

- **Whisper WASM(브라우저)** — 모델 40MB+ 다운로드, 폰에서 느리고 한국어가 약하다.
  §1-3 의 모바일 번들 예산과 정면 충돌한다. 탈락.
- **서버 자체 호스팅(faster-whisper)** — 우리 박스는 **2코어 vCPU, GPU 없음**이고
  거기서 야간 수집과 API 가 돈다. 30초 오디오 추론이 30~60초 걸린다. 실용성 없음.
- **GPU 임대** — 월 수십만 원. 건당 2.4원 × 월 30만 건 = 72만 원인 Gemini 보다 싸지 않다.

**권장 — 3단 하이브리드로 대부분을 0원으로 만든다**

| 단 | 무엇 | 비용 | 적용 |
|---|---|---|---|
| ① | 브라우저 `SpeechRecognition` 으로 받아쓰기 | **0원** | iOS Safari 14.5+ · Safari 14.1+ · Chrome 전부 · 삼성인터넷. Firefox 미지원(무시 가능) |
| ② | 규칙 파서로 숫자·전화·면적·월 추출 | **0원** | 항상. 즉시 화면에 채운다 |
| ③ | Gemini 는 **문맥이 필요할 때만** | 2.4원 | 아래 조건일 때만 호출 |

③ 을 부르는 조건 — **금액이 2개 이상** / **거래유형 낱말이 2개 이상이거나 0개** /
**'반환·대출·매도·잔금' 같은 선행조건 낱말이 보임** / 브라우저 STT 실패(iOS 미지원·권한 거부).

시험한 5개 중 3개가 ③에 해당했다. 다만 그 5개는 일부러 복잡하게 만든 문장이라
**실제 비율은 진짜 메모를 받아봐야 안다.** 짧은 메모가 많으면 평균 단가는 2.4원보다 훨씬 내려간다.

**주의**: 브라우저 STT 를 쓰면 고유명사 정확도가 떨어진다(단지명). §실측 5의 단지 DB 교정이
**더 중요해진다** — 자모 유사도 폴백을 여기서는 선택이 아니라 필수로 봐야 한다.



**설계 원칙 — 여기서 못 물러선다**

1. **오디오는 저장하지 않는다.** 변환 직후 폐기하고 텍스트만 남긴다.
   음성 파일은 유출됐을 때 피해가 텍스트와 비교가 안 된다.
2. **필드를 직접 덮어쓰지 않는다.** 제안까지만, 확정은 탭 한 번.
   잘못 들으면 24억이 42억이 된다. 되돌릴 수 없는 자동화는 넣지 않는다.
3. **실패해도 저장은 성공한다.** 구조화가 안 되면 받아쓴 원문만 `raw_text` 에 남긴다.
4. **국외이전 고지에 음성을 추가**해야 한다. 현재 고지는 텍스트 기준이다
   (법률 준수 항목의 중개사 약관 게이트와 같이 처리).
5. 손님과의 **통화 녹음이 아니라 중개사 본인의 메모**다. 둘은 법적 성격이 다르니 섞지 않는다.

**최적 접점.** 통화 종료 직후 팝업(§2-3)의 마이크 버튼.
"방금 통화 뭐였어요?" 에 말로 답하면 고객·요건·선행조건·다음 액션이 한 번에 갱신된다.
**타이핑이 0이 되는 지점**이고, 엑셀이 흉내조차 못 내는 지점이다.

**오프라인.** 20초 opus ≈ 35KB — 쓰기 큐에 넣어도 부담이 없다.
큐에 있는 동안만 로컬 보관하고 변환 성공 즉시 삭제한다(원칙 1의 예외를 최소 시간으로).


### 2-2-3. 문자·카톡 유입 — 음성보다 나은 원천 (실측 2026-08-05)

손님은 이미 **카톡과 문자로 요건을 보내고 있다.** 그게 원본이고, 중개사의 기억을 거치지 않는다.
음성 메모보다 이쪽이 낫다.

**실측 — 실제 메시지 5종(카톡 안드로이드/아이폰 붙여넣기, 문자 한 통, 손님 장문, 짧은 문자)**

규칙 파서는 **무너진다.** 정제된 음성 메모에서 70~80% 잡던 것이 실제 메시지에서는 이렇게 된다.

| 규칙 파서가 만든 값 | 실제 |
|---|---|
| 고객명 `사장` | "사장님 안녕하세요" 의 호칭 |
| 입주월 `8월` | **카톡 타임스탬프 `2026년 8월 4일`** 을 일정으로 오인 |
| 예산 `2,700,420,000원` | 출처 불명. 27억 뒤 숫자를 주워 먹음 |
| 거래 `매매·전세 동시` | 구분 불가 |

**이건 조용한 오류다.** 27억 420만원이 화면에 "27억" 으로 보이면 아무도 못 알아챈다.
음성 메모에서는 보조로 쓸 만했지만 **실제 메시지에서 규칙 파서는 보조가 아니라 해롭다.**

`gemini-2.5-flash` 는 **5/5 정확**했다.

- 카톡 타임스탬프를 입주일로 쓰지 않았다
- "9월말 보증금 나올 것 같아요" 를 입주일이 아닌 **선행 조건**으로 분류
- 장문 하나에서 **구함1 매매 주안 24~27억 + 구함2 전세 대안 9~13억** 두 요건을 분리
- 선행 조건 2개(전세보증금 9억 · 2026-09-30, 대출 5억) 추출
- 중개사 본인 발화(`나`)를 근거에서 제외

> **카톡 메시지 하나에서 참고 프로토타입의 거래 계획 화면이 통째로 나온다.**

**비용 — 음성보다 3.5배 싸다.** 건당 입력 190 · 출력 174토큰.
텍스트 입력 단가($0.30)를 쓰므로 오디오($1.00)보다 유리하다.
**건당 $0.00049 ≈ 0.7원.** 중개사 1,000명이 하루 10건이면 월 21만원(음성은 72만원).

**유입 경로 — 실현성 순위**

| | 경로 | 실현성 | 판단 |
|---|---|---|---|
| ① | **붙여넣기** (문자·카톡 복사 → 우리 입력창) | 전 플랫폼, 권한 0 | **1순위. 지금 당장 가능** |
| ② | **카톡 '공유하기' → PWA Share Target** | 안드로이드 ✓ / iOS ✗ | **2순위. `biz.webmanifest` 에 `share_target` 몇 줄** |
| ③ | **파일 가져오기** (카톡 대화 내보내기 txt, xlsx) | 전 플랫폼 | 3순위. 대량 이관용 |
| ④ | **문자 자동 읽기**(`READ_SMS`) | **Play 정책상 불가** | **접는다** |

④ 확인 결과 — Google Play 정책은 `READ_SMS` 를 기본 SMS 앱·백업·스팸탐지 등으로 한정하고
**CRM 은 명시적으로 `READ_SMS` 에서 제외**된다. 넣으면 심사에서 떨어진다.
대안인 알림 접근(`NotificationListenerService`)은 기술적으로는 되지만 **모든 알림을 읽어야** 해
개인정보 부담과 고지 의무가 크다 — 별건으로 판단할 일이지 이번 범위가 아니다.
**부수 확인: `READ_CALL_LOG` 는 CRM·업무 생산성 앱에 허용된다** → §2-3 통화 연동에 유리하다.

**보너스 — 카톡 붙여넣기는 화자가 딸려 온다**

```
2026년 8월 4일 오후 2:31, 김철수 : …     (안드로이드)
[김철수] [오후 2:31] …                    (아이폰)
```

형식은 다르지만 둘 다 **발신자와 시각**이 들어 있다. 화자 분리가 공짜로 되고,
**"손님 발화만 근거로 삼아라"** 가 가능해진다. 지시했더니 Gemini 가 정확히 지켰다.

**주의 — 날짜 환각.** 장문에서 대출 선행 조건에 `예정일 2026-09-30` 이 붙었는데 **원문에 없다.**
보증금 반환일을 끌어다 붙인 것이다.
→ 날짜는 **확신낮음으로 표시하고 근거 문장을 같이 보여준다.** 조용히 채우면 안 된다.

**음성 vs 문자 — 정리**

| | 음성 메모 | 문자·카톡 유입 |
|---|---|---|
| 원천 | 중개사가 요약해 말한 것 | **손님이 쓴 원본** |
| 정보 손실 | 중개사 기억을 거친다 | **없다** |
| 상황 제약 | 조용한 곳이 필요 | 없다 |
| 규칙 파서 | 70~80% 보조 가능 | **해롭다(조용한 오류)** |
| 건당 비용 | 2.4원 | **0.7원** |
| 고유 오류 | STT 고유명사 오인 | 날짜 환각 |

**문자·카톡이 주력이고, 음성은 원본이 없는 경우(전화 통화)를 메우는 보완재다.**

### 2-3. 전화가 트리거다 — 모바일 킬러 기능

통화 감지 사이드카(`design/biz_call_detect_설계안.md`, 미구현)와 결합한다.

- **수신 중** — "한구매님 · 구함 2건 · 병목: 전세보증금 반환 · 다음 액션: 반환일 확인"
- **통화 종료 직후** — "메모 한 줄" + `다음 액션 완료` 버튼. 여기서 안 남기면 영원히 안 남는다
- **모르는 번호** — "고객으로 저장할까요?" 한 번 탭

엑셀은 이걸 흉내조차 못 낸다. **모바일을 쓰는 이유 그 자체**가 된다.

### 2-4. 오프라인 — 데이터 모델에 영향을 준다

엘리베이터·지하주차장·현장에서 끊긴다. 이건 UI 문제가 아니라 **설계 문제**라 1단계부터 반영해야 한다.

- **조회 캐시**(IndexedDB) — 최근 본 고객 N명, 오늘·이번 주 일정, 내 매물장. PWA는 이미 있다
- **쓰기 큐** — 실패한 변경을 큐에 쌓고 온라인 복귀 시 재전송
- **멱등성 키** — 모든 쓰기 API가 클라이언트 생성 `client_uid` 를 받는다.
  재전송으로 같은 요건이 두 번 생기면 신뢰가 끝난다. **나중에 넣으면 API를 다 뒤집어야 한다**
- **충돌** — 서버 `updated_at` 비교. 다르면 조용히 덮지 말고 "다른 곳에서 바뀌었습니다" 를 보여준다
- 화면에 **동기화 상태**를 항상 표시(`저장됨` / `대기 3건` / `오프라인`). 조용한 실패가 최악이다

### 2-5. 알림

이미 있는 웹푸시(VAPID·TWA·iOS) 재사용. 새로 만들 게 없다.

- D-1 잔금·입주 / 병목 기한 임박 / 요건에 맞는 **새 급매 등장** / 새 상담·콕집요청
- 알림 탭 → 해당 고객 상세로 바로. 중간 단계를 두지 않는다

### 2-6. 태블릿

현장에서 손님에게 보여주는 화면. 그리드 **읽기**는 가능한 폭이다.
`641~1024px` 는 카드 2열 + 표 보기 허용, `1025px~` 부터 편집 그리드.

## 3. 자유 입력 — 원문 열 + 점진적 구조화

엑셀의 진짜 강점은 **아무거나 칠 수 있는 것**이다. 스키마를 강요하면 진다.

- 모든 요건 행에 **`원문` 열**. `강동구 고덕동 84 24~27억 10월입주` 라고 그냥 친다
- 시스템이 파싱해 **구조화 열을 제안**한다. 연한 배경 + 점선 밑줄, `Tab` 한 번이면 확정
- 구조화가 안 돼도 **행은 살아 있다.** 검색·정렬은 원문으로도 된다
- 데스크톱·모바일이 **같은 파서**를 쓴다(§2-2). 두 벌로 만들면 결과가 갈린다

### 사용자 정의 열

중개사는 자기 열을 만든다(`소개자`, `차량`, `애견동반`…).
`biz_needs.extra_json` 에 자유 키·값, 사무소별 열 정의는 `biz_sheet_columns`.
모바일 카드에는 **사용자가 고른 2개까지만** 노출(전부 보이면 카드가 무너진다).

## 4. 붙여넣기 = 도입 장벽의 90% (데스크톱)

중개사가 **지금 쓰는 엑셀을 그대로 붙여넣으면 원장이 채워져야** 한다.

1. 엑셀에서 범위 복사 → 그리드에 `Ctrl+V`
2. 헤더 자동 매핑 — `이름·성명·고객명`→고객, `연락처·전화·핸드폰·HP`→전화, `예산·금액·희망가`→예산 …
3. **매핑 확인 1회** — 틀린 것만 드롭다운으로 고친다
4. 중복 감지 — 이름+전화가 같으면 "3건이 기존 고객과 겹칩니다. 합칠까요 / 새로 넣을까요"

**함정**: 엑셀에서 전화번호를 숫자 서식으로 저장했으면 `01012345678` → `1012345678` 로 앞 0이
이미 날아가 있다. 감지해서 **물어보고** 복원한다(조용히 고치지 않는다).

모바일에는 붙여넣기를 넣지 않는다. 폰에서 표를 붙여넣는 사람은 없다.
대신 **파일 업로드**(카톡으로 받은 xlsx를 폰에서 열어 공유 → 우리 앱)는 열어 둔다.

## 5. 계산 열 — 엑셀이 못 만드는 열

사용자 입력 열과 **시각적으로 구분**한다(연회색 배경, 자물쇠, 편집 불가). 항상 최신.

| 계산 열 | 내용 | 근거 |
|---|---|---|
| **매칭** | 이 요건에 맞는 매물 N건 | 우리 매물장 → 전국 매물 → 급매 엔진 |
| **시세** | 같은 단지·평형 최근 실거래 / 현재 최저호가 | `transactions`, `listings_current` |
| **경쟁** | 광고 배율(매도 경쟁 강도) | 광고 vs 물건(Σ1/same_addr_cnt) |
| **D-day** | 다음 일정까지 남은 날 | `biz_events` |
| **준비상태** | 선행 조건 전부 완료 여부 | `biz_plan_conds` |
| **다음 액션** | 병목에서 파생 | 규칙 + 중개사가 덮어쓰기 가능 |
| **최근 연락** | 마지막 통화·문자·상담 | `biz_call_events`, 상담리드 |

- 데스크톱: 열로 보인다. 셀 클릭 → 오른쪽 패널에 매물 목록 → 콕집요청 제안으로 연결
- 모바일: 카드에 **매칭·D-day·다음 액션 세 개만** 띄운다. 나머지는 상세에서

## 6. 시트끼리 잇는다

```
고객 ──┬── 요건 (구함·내놓음)  ── 매칭 → 매물
       ├── 일정 (계약·중도금·잔금·입주·만기)
       └── 계약 (계약서 파싱)
```

- 요건 시트의 `고객` 열은 고객 시트를 참조하는 드롭다운 — **오타로 중복이 생기지 않는다**
- 계약서를 올리면 고객·요건·일정이 **동시에** 생긴다. 세 시트에 옮겨 적을 일이 없다
- 콕집요청이 들어오면 요건 행으로 **승격**된다(`biz_needs.src_request_id`)

```
biz_plan_links       연결(다대다) from_kind(base|cond), from_id, to_kind(cond|need), to_id

biz_sheet_columns    사무소별 열 정의  realtor_id, key, label, type, width, order, hidden, mobile_show
biz_cell_log         셀 변경 이력      table, row_id, col, before, after, user_id, at
                                       -- 되돌리기 + 직원 여러 명일 때 "누가 바꿨나"
```

★ 표시가 **모바일 때문에 1단계부터 들어가야 하는 것**이다. 나중에 넣으면 API를 전부 뒤집는다.

`biz_plan_links` 를 다대다로 두는 이유: 프로토타입에서도 선행 조건 2개가 목표 2개에 **교차로** 걸린다
(전세보증금 반환 → 매매·전세 양쪽, 대출 한도 → 양쪽). 1:N 이면 그 그림을 못 그린다.

### 파생값은 저장하지 않는다

병목 = 미완료 선행 조건 중 `gate` 가 이르고 `expected_date` 가 빠른 것. 준비상태·다음 액션도 여기서 계산.
**저장하면 반드시 어긋난다** — 조건을 바꿨는데 상태가 그대로면 화면 전체를 못 믿게 된다.

### 저장·동기화

- 셀/필드 편집 → 즉시 `PATCH`(낙관적 반영). 실패 시 빨간 테두리 + 재시도 큐
- 모든 쓰기는 `client_uid` 멱등. 같은 uid 재전송은 갱신이지 생성이 아니다
- 충돌은 **last-write-wins + 변경 표시**. 실시간 동시편집(CRDT)은 이 규모에 과하다

## 9. 뷰 전환 — 같은 데이터, 네 얼굴

| 뷰 | 데스크톱 | 모바일 |
|---|---|---|
| **그리드** | 기본 | 읽기 전용 표 보기(선택) |
| **원장 펼침** | 거래 계획 곡선 플로우(SVG) | 세로 3단 스택(기반→조건→목표) |
| **캘린더** | 월 그리드 + 목록 | 주간 스트립 + 목록 |
| **보드** | 상태별 칼럼(탐색→비교→협상→계약) | 상태 필터 칩 + 카드 |

곡선 커넥터는 좁은 화면에서 읽히지 않는다. **모바일에서는 버린다** — 축소해서 넣지 않는다.

- 모바일(비즈앱): 하단 탭 **4개로 고정** — `오늘 · 고객 · 매물 · 더보기`.
  나머지는 전부 `더보기` 안으로. 탭이 5개를 넘으면 엄지로 못 누른다

## 11. 단계 — 각 단계는 데스크톱+모바일이 함께 나온다

| 단계 | 데스크톱 | 모바일 | 이 단계로 얻는 것 |
|---|---|---|---|
| **0** | 대시보드 2단(현황+일정) | — | **완료 2026-08-05** |
| **1** | `biz_needs`(★필드 포함) + 그리드 **읽기** | 고객 카드 목록 + 상세 | 요건이 한 화면에 보인다 |
| **2** | **셀 편집·키보드·IME·붙여넣기·내보내기** | **한 줄 입력 + 규칙 파서** | **엑셀에서 이사 온다** |
| **3** | 계산 열(매칭·시세·D-day·최근 연락) | 카드에 매칭·D-day·다음 액션 | 엑셀로 못 돌아간다 |
| **4** | 오프라인 캐시·쓰기 큐·동기화 표시 | 같음(여기가 주 무대) | 현장에서 끊겨도 쓴다 |
| **5** | 원문 AI 파싱 제안 + 사용자 정의 열 | **문자·카톡 붙여넣기·공유하기 유입**(§2-2-3) · 음성 메모(§2-2-1) | 입력이 빨라진다 |
| **6** | 거래 계획 곡선 플로우 + 병목·다음 액션 | 세로 3단 스택 | 프로토타입 화면 완성 |
| **7** | 캘린더 양방향 + 병목 알림 | 웹푸시 + 통화 트리거 | 손 안 대도 굴러간다 |
| **8** | 보드 뷰 · 좌측 레일 IA | 하단 탭 4개 재편 | 마무리 |

**2단계가 승부처다.** 1단계는 준비, 3단계는 잠금.
2단계 없이 3단계로 뛰면 "예쁜데 입력을 못 하는" 지금 상태가 반복된다.

**4단계(오프라인)를 뒤로 못 미루는 이유**는 §8의 ★ 필드 때문이다. 스키마는 1단계에 넣고
동작만 4단계에서 켠다. 반대로 하면 API를 다시 짠다.

## 12. 위험과 함정

| 위험 | 대응 |
|---|---|
| 한글 IME에서 커서가 튄다 | `composition` 구간 키 핸들러 차단, 실기기 4종 실측 |
| 전화번호 앞 0 소실 | 붙여넣기 시 감지 후 **물어보고** 복원 |
| 폰에서 첫 화면이 안 뜬다 | 그리드는 데스크톱 폭에서만 `lazy()`. 모바일 번들 예산을 정해 CI에서 감시 |
| 오프라인 재전송으로 중복 생성 | `client_uid` 멱등 — **1단계부터** |
| 저장 실패를 모른 채 계속 입력 | 실패 셀 표시 + 상단 배너 + 동기화 상태 상시 노출 |
| 동시 편집 충돌 | `updated_at` 비교, "○○님이 방금 바꿨습니다" |
| 개인정보 노출 | 한 화면에 전화번호 수백 개 — 직원 권한(owner/staff) 분리, 열람 로그, 마스킹 토글. **분실 위험이 큰 폰에서 더 중요** |
| 한 줄 파서가 자꾸 틀린다 | 규칙 우선·즉시 반영, 실패해도 `raw_text` 로 저장은 성공. **저장을 막지 않는다** |
| 음성 인식이 무음에서 프롬프트를 되뱉는다 | **실측 확인됨.** `response_schema` + `들림(boolean)` 강제 + 업로드 전 RMS 게이트 |
| 음성이 단지명을 틀린다 | 우리 단지 DB 로 교정. 한 글자 오류는 LIKE 로 안 잡히니 **자모 유사도 폴백** 필요 |
| 음성이 금액을 잘못 듣는다 | 필드를 덮어쓰지 않고 **제안만** 한다. 24억이 42억이 되는 자동화는 넣지 않는다 |
| 만들어도 안 쓴다 | 2단계 완료 시점에 실제 중개사 3명에게 **자기 엑셀을 붙여넣게** 하고, **폰으로 하루 써보게** 한 뒤 결정 |

## 13. 먼저 정해야 할 것

1. **개방 시점** — `/biz/*` 는 전부 관리자 가오픈이다. 법률 준수 메모상 **중개사 약관 동의 게이트가
   캘린더·고객원장 개방의 선행 조건**이다. 만들되 게이트 뒤에 둘지, 게이트를 먼저 칠지.
2. **실제 엑셀 확보** — 지금 쓰는 엑셀 5~10개를 봐야 열 매핑 사전과 한 줄 파서 규칙을 만든다.
   **가장 먼저 필요한 것.** 이게 없으면 2단계 전체가 추측이 된다.
3. **모바일 우선순위** — 통화 트리거(§2-3)는 네이티브 사이드카가 필요하다(미구현).
   7단계까지 미룰지, 앞당겨 모바일 킬러 기능을 먼저 확보할지.
   다만 **문자·카톡 유입(§2-2-3)은 사이드카 없이 지금 가능**하므로 이쪽이 먼저다.
4. **역할 용어** — `주안 / 대안 / 보유` 를 현장 용어 그대로 쓸지.
5. **선행 조건 프리셋** — 전세보증금 반환·주담대 한도·기존 주택 매도·전입 가능일 등 실제 목록.
6. **음성 개방 범위** — 기술은 검증됐다(§2-2-1). 남은 건 **국외이전 고지에 음성 추가**와
   중개사 약관 게이트다. 5단계까지 기다릴지, 게이트가 열리는 시점에 바로 붙일지.
7. **범위** — 3단계까지를 1차로 볼지, 6단계(거래 계획)까지 한 묶음으로 볼지.
