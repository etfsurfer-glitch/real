# 상업용 빌딩 특성 데이터 — 정리 구상

작성 2026-10-19. 사용자 수집자료(구글드라이브 `월별임대안내문`) 실사 후 전면 개정.
입지(상권) 분석인 `design/academy_commercial/상업용_입지분석_계획서.md`와 **대상이 다르다** —
그건 '어느 동이 좋은가'(지역 축), 이건 '이 빌딩은 어떤 빌딩인가'(건물 축)다.

## 1. 자료 실사 결과

드라이브 폴더 `월별임대안내문` = **오피스 임대안내문(leasing flyer) 월별 아카이브**.
커넥터 스코프로는 안 보여 브라우저로 확인했다.

|---|---|---:|---|
| CBRE | CBRE | 14 (+2025 하위폴더) | 2025-10 ~ 2026-10 |
| Genster | GenstarMate (CRE·LM 2종) | 13 | 2024-11 ~ 2026-04 |

전체 1만 페이지 규모로 추정된다.

## 2. 재평가 — 이 자료는 '못 메운다'고 썼던 구멍을 메운다

직전 구상에서 *"상업 임대차는 신고의무가 없어 실거래가 없다 → 시장 축은 영원히 호가 추정"*
이라고 적었다. 그런데 이 자료에는 **보증금·임대료·관리비가 빌딩·층 단위로, 월별로** 찍혀 있다.
자문사·PM사가 직접 산정해 고객에게 배포한 공식 호가다. 네이버 광고보다 훨씬 정제돼 있고,
한국 오피스 시장에서 이 시계열을 쥔 곳은 자문사 본인들뿐이다.

**즉 이 자료가 자산의 본체이고, 공부(대장) 데이터는 그것을 거는 못이다.** 순서를 뒤집는다.

### 여기서 나오는 설계상 핵심 3가지

1. **발행사마다 공개 수준이 다르다.** CBRE는 임대료·관리비를 비워 두고(문의), 에스원은 공개한다.
   → 한 빌딩을 여러 발행사가 동시에 다루므로 **겹쳐서 메운다.** 같은 달 같은 빌딩 값이
   발행사마다 다르면 그 차이 자체가 신호다(협상 여지·실수취율).
2. **주소 체계가 다르다.** CBRE는 지번, 에스원은 도로명. 식별 로직이 둘 다 받아야 한다.
3. **단위가 다르다.** CBRE는 ㎡+평 병기, 에스원은 평 단독. 임대료는 원/3.3㎡.
   연면적을 평으로만 주면 ㎡ 환산 오차가 생기니 **원문 문자열을 같이 보관**한다.

## 4. 데이터 모델 — 3축(빌딩 × 발행호 × 발행사)

빌딩 스펙은 거의 안 변하고, 공실·임대료는 매달 변한다. 분리한다.

```sql
bld                 -- 빌딩 마스터(불변 축). 발행사 무관 1행
  bld_key PK, pnu, mgm_pk, 권역(CBD/GBD/YBD/기타/수도권),
  name, name_en, addr_road, addr_jibun, lat, lng,
  tot_area_m2, floors_up, floors_down, built_ym, remodel_ym,
  eff_rate, elevator_cnt, elevator_desc, parking_cnt, parking_desc,
  std_floor_lease_py, std_floor_excl_py, subway_desc

bld_issue           -- 발행호(발행사×월) 메타
  issue_id PK, publisher, issue_ym, src_file, n_pages, parsed_at

bld_vacancy         -- 발행호 × 빌딩 × 층 : 공실
  issue_id, bld_key, floor_label, lease_py, lease_m2, excl_py, excl_m2,
  avail_from_raw, avail_from_ym
  PRIMARY KEY(issue_id, bld_key, floor_label)

bld_rent            -- 발행호 × 빌딩 × 층(또는 '기준층') : 임대조건
  issue_id, bld_key, floor_label,
  deposit_per_py, rent_per_py, mgmt_per_py,   -- 원/3.3㎡
  free_rent_raw, note_raw
  PRIMARY KEY(issue_id, bld_key, floor_label)

bld_contact         -- 담당자. 격리 보관, 외부 노출 금지(§7)
bld_unmatched       -- 빌딩 식별 실패분. 버리지 않는다
```

빌딩 마스터는 **발행호마다 덮어쓰지 않는다.** 스펙이 바뀌면(리모델링·증축) `bld_attr`에
직전 구상의 출처추적 방식(값·출처·관측일·신뢰도)으로 이력을 남긴다.

## 5. 빌딩 식별 — 여기가 제일 어렵다

자료에 지번이 항상 있지는 않다(에스원은 도로명만). 3단 폴백:

```
① 지번 있으면  → 법정동코드+본번+부번 → title_cache(표제부 694만 동) 직접 대조
② 도로명만     → VWorld 지오코더 → PNU → 같은 대조
③ 둘 다 애매   → 빌딩명 + 권역으로 title_cache bldNm 역검색
검증: 연면적 ±5%, 준공년도 ±1년, 지상층수 일치 → 2개 이상 맞아야 채택
★ 유일해만 채택. 모호하면 bld_unmatched 보류 — 오귀속 0 원칙
```

예상 함정:
- **신축·예정 건물은 대장에 없다.** 이을타워는 2026년 10월 준공 **예정**이라 표제부 미등재
  가능성이 높다 → `pending` 상태로 두고 매달 재시도.
- **빌딩명은 흔하다.** 'FN Tower'가 대치·판교에 각각 있다(에스원 색인 실측). 권역 없이 이름만으로 매칭 금지.
- **같은 빌딩을 발행사마다 다르게 쓴다.** `을지트윈타워`(CBRE 색인) = `(스퀘어원) 을지트윈타워`
  (별도 단일 빌딩 파일). 별칭 테이블 필요.

## 6. 추출 방법 — P0에서 결정할 갈림길

PDF에 **텍스트 레이어가 있는지**가 전체 공수를 가른다.
- 있으면: `pdfplumber`로 표 추출 → **발행사별 파서 7개**(양식이 제각각이라 공통 파서는 불가)
- 없으면(이미지 PDF): OCR 또는 비전 모델 — 1만 페이지면 비용이 한 자릿수 배 커진다

신호: 파일명에 `_unlocked`가 붙은 게 둘 있다(`December2025_unlocked`, `January2026_unlocked`).
보안이 걸려 있던 걸 푼 흔적 → **텍스트 기반 PDF일 가능성이 높다**(복사 제한을 풀려고 unlock).

분량 감각: 권역별 빌딩 150~250개 × 24개월 × 발행사 7 → 레코드는 수만~수십만 행.
**스크린샷으로 한 장씩 읽을 양이 아니다.** 프로그램 파싱이 전제다.

## 7. 개인정보·이용범위 — 먼저 못 박을 것

1. **담당자 개인정보.** 모든 페이지에 실명·휴대폰·이메일이 찍혀 있다(CBRE 4명, 에스원 2명).
   파싱 시 `bld_contact`로 격리하고 **외부 노출·대외자료 금지**.
   우리 '별명만 노출' 정책([[naverreal-nickname-only-privacy]])과 같은 선에서 다룬다.
2. **저작권.** 각 사가 고객에게 배포한 영업자료다. 내부 분석·우리 데이터 보강에 쓰는 것과,
   수치를 원문 표째로 재배포하는 것은 다르다. **집계·가공 지표로만 외부에 내보내고
   원문 표·도면·사진은 싣지 않는** 선을 권한다. 마켓리포트(CBRE/JLL 발간물)는 더 엄격히 — 인용만.

## 8. 쓸모 — 이걸 모으면 무엇이 되나

- **빌딩별 임대료·공실 월별 시계열**: 24개월. 국내에 공개된 곳이 사실상 없다.
- **권역 지수의 바닥 데이터**: 마켓리포트가 주는 CBD/GBD/YBD 공실률·임대료를 우리가 빌딩 단위로
  재현·검증할 수 있다. 리포트는 결론만 주고 원데이터를 안 준다.
- **렌트프리·실질임대료**: 명목 임대료와 공실 지속기간을 겹치면 실질 조정폭이 보인다.
- **우리 광고 데이터와 교차**: `listings_office`의 호가 vs 자문사 공식 임대료 → 광고 호가의
  왜곡 계수를 처음으로 실측할 수 있다. 직전 구상의 `yield_est`가 '참고'에 머문 이유가 이것이었다.

## 9. 단계

- **P0 — 추출 가능성 확인(0.5일)**: 샘플 3개(CBRE·에스원·JLL) 텍스트 레이어 확인,
  발행사 1곳 파서 시제품 → **추출 정확도 실측**. 여기서 전체 공수가 확정된다.
- **P1 — 파서 + 빌딩 매칭(2~4일)**: 발행사별 파서, §5 식별, `buildings.sqlite` 적재, 매칭률 보고.
- **P2 — 전량 적재(1~2일)**: 65개 PDF 소급 → 빌딩별 시계열 완성.
- **P3 — 공부 결합**: 표제부 24필드 전국 배치(직전 구상 §3 — `title_full_ref` 파서는 이미 있고
  전국 배치만 안 돌렸다. 6.9만 콜 ≈ 키 2개로 4일, 무인).
- **P4 — 활용**: 교차검증·지수 재현·광고 왜곡계수.

## 10. 지금 막힌 것

**PDF를 로컬로 내려받아도 되는지.** 드라이브 미리보기 스크린샷으로는 1만 페이지를 못 읽는다.
P0부터 실제 파일이 필요하다. 허락해 주시면 `design/commercial_building/raw/<발행사>/`에
내려받아 작업한다(원본은 손대지 않고 복사만).
