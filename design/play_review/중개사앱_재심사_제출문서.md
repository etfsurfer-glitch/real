# 콕집 중개사앱 Play 재심사 제출 문서

패키지 `com.koczip.realtor` · 제출 버전 **1.0.2 (versionCode 11)** · 작성 2026-10-15

반려 4건(2026-10-04)을 모두 다룬다. 세 건은 **SMS/통화 기록 정책 선언** 하나에서,
한 건은 **로그인 자격증명**에서 나왔다.

## 0. 반려 원인 — 무엇이 실제로 잘못돼 있었나

| 반려 | 진짜 원인 |
|---|---|
| 권한 액세스 사용자 메시지 누락 | 권한 요청 화면에 **닿을 길이 없었다**(아래 ★) |
| 요청 권한이 핵심 기능과 불일치 | 스토어 등록정보·앱 이름이 '매물장·매물점검'만 말하고 발신자 확인을 한 줄도 안 알렸다 |
| 핵심 기능 확인 불가 | 로그인 전에는 발신자 카드가 **아예 안 떴다**(코드가 토큰 없으면 return) |
| 로그인 자격증명 기기 제한 | 로그인이 휴대폰 SMS 인증뿐 — 심사자는 문자를 못 받는다 |

★ 권한 화면(`CallSetupActivity`)에 닿는 경로가 셋 다 막혀 있었다.
① 첫 실행 분기는 `토큰 보유자`만 대상 → 신규 설치자는 통과 못 함
② `koczip://call-enable` 은 웹 로그인 필요
③ `koczip://call-setup` 과 홈 바로가기는 **`shortcuts.xml`이 빈 파일**이라 존재하지 않았다

빈 파일의 원인은 `app/build.gradle`의 `generateShorcutsFile` 태스크다. 본문이
`task foo { ... }` 형태라 **설정 단계마다 무조건 실행**돼, `dependsOn`과 무관하게
매 빌드에서 `shortcuts: []` 기준 빈 파일로 덮어썼다. 2026-10-05에 바로가기 문자열만
추가하고 XML을 손으로 써 둔 수정이 빌드와 동시에 지워진 것이다. 태스크를 제거했다.

## 1. 권한 선언 양식 (Permissions Declaration Form)

### 1-1. 사용 사례 — 그대로 유지
**`Caller ID, spam detection, and/or spam blocking`**

변경하지 않는다. 이 앱의 `READ_CALL_LOG` 사용은 정의 그대로의 발신자 확인이다 —
걸려온 번호를 확인해 **전화를 받기 전에** 통화 화면 위에 누구인지 띄운다.
차단·필터링은 하지 않는다(`respondToCall`에 빈 `CallResponse`로 항상 통과시킨다).

정책상 이 사용 사례는 기본 전화 핸들러가 아닌 앱에 주는 **예외(Exception)**에 해당하고,
요건은 ①권한이 핵심 기능을 가능케 하고 ②현재 다른 방법이 없을 때다. 둘 다 충족한다.

근거를 하나 더 보탠다. 안드로이드 OS 자신이 이 앱을 그 범주로 부른다. 역할 요청 시
시스템이 띄우는 대화상자 문구가 **"Set 콕집 중개사 … as your default caller ID & spam
app?"** 이다(에뮬레이터 Android 15 실측). 선언한 사용 사례명과 글자 그대로 일치한다.

### 1-2. "다른 방법이 없다"는 근거 — 실측 데이터

문서상 대안은 `CallScreeningService`(`ROLE_CALL_SCREENING`)다. 우리는 그것을
**먼저 구현했고 기본 경로로 쓰고 있다.** 그런데 실제 기기에서 거의 동작하지 않는다.

앱에 심은 원격 진단(`/biz/call-diag`) 실측 — 삼성 **SM-S938N / Android 16 (SDK 36)**,
발신자 확인 역할 **보유 상태(`역할보유=true`)**, 통화 기록 권한 허용 상태, 수신 24건:

| 지표 | 값 |
|---|---|
| 수신 벨 세션 | **24건** |
| `onScreenCall()` 실제 호출 | **6건 (25%)** |
| 발신자 카드 — 스크리닝 경로 | 6장 |
| 발신자 카드 — **통화 기록 경로** | **18장 (75%)** |
| 라이브 경로가 못 잡아 통화 기록으로만 번호 복구 | **14건** |

원인은 기기에 **다른 `CallScreeningService`가 함께 등록돼 있는 것**이다. 같은 진단의
`other_screen` 필드가 `com.samsung.android.dialer`를 가리킨다. 안드로이드는 스크리닝
역할을 한 앱에만 바인딩하므로, 제조사 기본 다이얼러가 대부분의 수신을 가져간다.
역할을 쥐고 있어도 `onScreenCall`이 네 번 중 세 번은 오지 않는다.

> 요약: 발신자 확인 기능의 **75%가 `READ_CALL_LOG` 경로에서 나온다.**
> 이 권한을 빼면 한국 시장 점유 1위 제조사 기기에서 핵심 기능이 네 번 중 세 번 실패한다.
> 대안을 안 써서가 아니라, 대안을 구현해 두고 실측했더니 동작하지 않아서다.

### 1-3. 권한 사용 범위 — 최소

- 벨이 울리는 **그 순간, 최근 통화 1건**만 읽어 번호를 얻는다(`CallLogHelper.lastRecentCall`,
  60초 이내 항목만, `LIMIT 1`).
- 통화 기록 **목록을 열람·저장·업로드하지 않는다.** 서버로 가는 것은 통화 1건의
  메타데이터(번호·방향·시작시각·통화시간)뿐이고, 그것도 로그인한 중개사 본인의
  고객 타임라인에 쌓기 위한 것이다.
- **통화 내용·녹음은 수집하지 않는다.** 녹음 권한 자체가 없다.
- 시스템 권한 프롬프트 **직전에 명시적 공개(prominent disclosure)** 대화상자를 띄우고
  긍정 동의를 받는다(`CallSetupActivity.showDisclosure`).
- 권한을 거부해도 앱의 나머지 기능은 정상 동작한다.

### 1-4. 심사자 확인 절차 — 양식의 '확인 방법' 칸에 그대로 넣을 문구

```
앱을 설치해 처음 열면, 웹 화면보다 먼저 '전화 고객알림' 안내 화면이 뜹니다.
로그인·회원가입·전화번호 인증이 전혀 필요 없습니다.

1) 첫 화면에서 [발신자 카드 미리보기 (예시)] 를 누르면, 실제 수신 때와 똑같은
   발신자 카드가 즉시 표시됩니다. 핵심 기능의 결과물을 전화를 걸지 않고 확인할 수 있습니다.

2) [전화 알림 켜기 (발신자 확인 설정)] 을 누르면
   ① 안드로이드 '발신자 확인 앱으로 설정' 역할 요청 대화상자
   ② 앱 자체 '접근 권한 안내'(어떤 데이터를 왜 쓰는지 명시적 공개) → [동의하고 계속]
   ③ 전화 상태 / 통화 기록 / 알림 런타임 권한 프롬프트
   순서로 표시됩니다.

3) 권한을 허용한 뒤 테스트 기기로 전화를 걸면, 통화 화면 위에 발신자 카드가 뜹니다.

4) 화면 아래 '내 폰 설정 점검'에서 각 권한의 허용 여부를 바로 확인할 수 있습니다.

5) 나중에 다시 열려면: 홈 화면에서 앱 아이콘을 길게 눌러 '전화 알림 설정' 바로가기를
   선택하세요.

웹 화면(매물장 등)까지 보시려면 아래 테스트 로그인을 사용하세요.
```

## 2. 로그인 자격증명 (Play Console → 앱 콘텐츠 → 로그인 세부정보)

기기 인증에 묶이지 않는 두 경로를 준다. 둘 다 SMS·실기기 연결이 필요 없다.

### 2-1. 앱 안 전화 고객알림 로그인 (선택 — 권한 확인에는 불필요)

```
휴대폰 번호: 010-0000-0000
인증번호:   000000

· [인증번호 받기] 를 누르면 문자를 보내지 않고 바로 인증번호 입력칸이 열립니다.
  위 고정 번호 000000 을 입력하세요.
· 이 계정은 심사용 데모 사무소에 연결돼 있으며 실제 회원 데이터에 접근하지 않습니다.
· 발신자 확인 권한을 확인하는 데에는 이 로그인이 필요하지 않습니다(위 1-4 참고).
  이 로그인은 카드에 '고객 이름'까지 채워 보고 싶을 때만 쓰십니다.
```

### 2-2. 웹 화면(매물장·고객관리) 전체 확인 — URL 한 줄

```
https://koczip.com/biz?demo=play-review-2026

위 주소를 열면 심사용 데모 계정으로 자동 로그인됩니다.
아이디·비밀번호·문자 인증이 필요 없습니다.
```

> ⚠ 2-1의 고정 코드는 서버 `.env` 의 `BIZ_REVIEW_PHONE` / `BIZ_REVIEW_CODE` 가 설정돼
> 있을 때만 동작한다. **심사 통과 후 이 두 값을 지우면 경로가 통째로 사라진다.**

- **녹화 중 한 번도 로그인하지 말 것.** "로그인 없이 핵심 기능이 확인된다"가 증명 포인트다.
- 화면 녹화 + 통화를 동시에 하려면 다른 폰에서 걸고 피촬영 폰을 내장 녹화기로 녹화.
- 카드가 뜨는 순간을 반드시 포함. 이게 없으면 또 "확인 불가"가 된다.
