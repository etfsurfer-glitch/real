# 비단지 매물 콕집 전환 개선 계획 (2026-11-12)

대상: 빌라·원룸·단독 / 상가·사무실·지식산업센터·건물·공장 / 토지
전제: 수집 DB는 읽기 전용 원천, 광고 문구는 옮기지 않음, 콕집매물은 시험 중이라 실제 중개사 동의 유도·연락 금지.

## 1. 법 기준 다시 정리 (11-11 점검 내용 정정)

근거: 공인중개사법 18조의2 ②, 시행령 17조의2 ②, 「중개대상물의 표시·광고 명시사항 세부기준」 고시.

11-11 보고에서 바꿀 점:
- **지번은 막는 요인이 아니다.** 상가·사무실·공장·건물과 단독은 의뢰인이 요청하면 동까지만 표시할 수 있다. 원 광고가 지번을 숨긴 것을 '의뢰인 요청'으로 보고 동까지 표시하면 된다. PNU로 지번을 채워 공개하는 방식은 하지 않는다. PNU는 내부 대조용으로만 쓴다.
- **상가·사무실·공장·건물의 관리비는 필수가 아니다.** 지금 게이트가 관리비를 필수로 보고 있어서 필요 이상으로 '게시 전'에 묶인다.
- **비주거의 방향 기준은 '주출입구'로 정해져 있다.** 방향 값이 있으면 기준은 주출입구로 표시하면 된다. 방향 값 자체가 없을 때만 막는다.
  - 원본 상세로 확인(2026-11-12, 무작위 표본): 상가 40건 중 방향 36·기준 칸 0, 사무실 40건 중 37·0, 지산 12건 중 11·0, 공장 12건 중 11·0.
  - 기준 칸은 값이 비어 있는 것이 아니라 **칸 자체가 없다.** 주거(빌라·단독·상가주택 건물)는 같은 칸에 '거실 기준'·'안방 기준'이 들어 있다.
  - 즉 원 등록 화면이 비주거에는 기준을 묻지 않고 방향만 받는다. 기준이 주출입구로 정해져 있기 때문으로 본다. 방향 값은 그 기준으로 입력된 값이라 '주출입구 기준'으로 표시해도 된다.
  - 방향이 없는 약 10%만 '게시 전'이 된다.
  - 지산·공장은 목록(지역 DB)에 방향이 0%라 상세를 꼭 받아야 한다. 상세에는 92% 있다.
- **비주거는 층을 고·중·저로 쓸 수 없다.** 고·중·저 표기는 주택에서 의뢰인이 요청할 때만 허용된다. 지금은 모든 층 있는 유형에 허용하고 있다.

## 2. 지금 코드와 법 기준의 차이

| 위치 | 지금 | 고칠 것 |
|---|---|---|
| `scripts/kok_sync.py` `publish_check` 방향 | `HOUSING`(주택)만 검사 | 층 있는 건축물 전부와 단독(`FLOORED ∪ DDDGG`)으로 넓힘. 방향 기준 값도 검사 |
| `publish_check` 층 | 층 있는 유형 전부 고·중·저 허용 | 고·중·저는 주택만. SG·SMS·GM·GJCG·지산은 정확한 층 |
| `publish_check` 관리비 | SG·SMS도 필수, DDDGG는 검사 안 함 | SG·SMS·GM·GJCG·지산은 선택. VL·OR·DDDGG·OPST는 필수, '관리비 없음'을 값으로 받음 |
| `scripts/local_api.py` `_kok_required` | SG·SMS 관리비 필수, GM·GJCG 방향 없음, SG·SMS 방·욕실 없음 | 위 표와 같게. 방·욕실은 고시 확인 뒤 결정 |
| 소재지 표시 방식 | 지번 한 가지 | `address_mode` = `jibun` / `dong` 추가. `dong`은 단독·비주거만 허용, 빌라(공동주택)는 지번 필수 |
| 유형 목록 `_KOK_PTYPES` | 지식산업센터·재개발 없음 | 지식산업센터(APTHGJ) 추가. 재개발(JGB)은 이번 범위에서 뺌 |
| 관리비 값 | 금액이 없으면 '빠짐' | `mgmt_type`에 '없음' 추가. '없음'과 '안 적음'을 구분 |

이 차이는 콕집 전용 등록(라운지 직접 등록)에도 똑같이 걸려 있다. 그래서 전환보다 먼저 고친다.

## 3. 전환 구조

### 원천
- 비단지 9개 지역 DB(`listings_{sangga,office,villa,house,land,factory,building,knowledge,redev}.sqlite`)를 `mode=ro`로 읽는다. 수집기와 지역 DB에는 콕집 로직을 넣지 않는다.
- 1차 대상은 `attribution='realtor'`이면서 `realtor_id`가 동의 사무소인 광고뿐이다. 등록번호로 귀속한 광고(`office_attribution.sqlite`)는 오귀속이 0이라는 보장이 없어 1차에서 뺀다.
- 지역 DB는 3일 롤링이다. 동기화가 하루 이상 멈추면 놓치는 매물이 생긴다. 그래서 kok_sync 비단지 단계가 실패하면 텔레그램으로 알린다.

### 저장 (`data/kok.sqlite`)
- `kok_listings`를 그대로 쓴다. 출처 구분 `src`(complex / region)와 비단지 칸을 더한다.
  - `ptype`, `address_mode`, `addr_dong`, `jibun`(원 광고가 지번을 공개한 경우만), `pnu`(내부용, 화면에는 안 나감)
  - `land_m2`, `land_use`(지목), `approve_ymd`, `parking`, `bld_use`(대장 주용도), `premium`(권리금, 광고 표시 값)
- 상세는 지금과 같이 kok_sync에서 받는다. 하루 처리량 `KOK_DETAIL_PER_RUN`, 7일 TTL. 받는 값은 노출 주소, 지번 공개 여부, PNU, 방향과 기준, 관리비 종류·비목, 사용승인, 주차, 대지·연면적, 입주.

### 우리가 직접 채우는 값 ("계산할 수 있는 건 우리가")
- **건축물대장 대조:** PNU로 표제부를 조회한다. 매물 점검에서 쓰는 `collector.ondemand_ledger`를 그대로 쓴다. 사용승인일, 총 층수, 주차대수, 주용도를 채운다. 광고 값과 다르면 점검 항목(warn)으로 띄운다. 공개되는 값은 대장 값이다.
- **토지:** PNU로 VWorld 지적을 조회해 지목과 대장 면적을 채운다. 개별공시지가는 이미 쓰는 키로 함께 붙인다.
- **좌표:** 원 광고 좌표를 쓴다. 역지오코딩 주소는 소재지로 쓰지 않는다(필지가 어긋날 수 있음).

### 게시 게이트
- `publish_check`를 1절 표대로 바꾼다. 비단지 전환분도 같은 `live / hold` 흐름을 탄다.
- 라운지 '게시 전' 목록에 사유가 나오고, 중개사가 빠진 항목(방향 기준, 관리비, 정확한 층 등)을 채우면 바로 다시 계산한다.
- 빌라인데 지번이 숨겨진 광고는 hold로 둔다. 사유는 '공동주택은 지번 표시 필요'.

## 5. 지키는 원칙
- 원 광고가 숨긴 지번은 공개하지 않는다. PNU는 대조용이다.
- 광고 문구(설명·특징·태그)와 사진 CDN은 옮기지 않는다. 사진·설명은 등록자가 콕집에 직접 올린다.
- 대장·지적에서 가져온 값과 광고 값이 다르면 대장·지적 값을 보여 주고, 라운지 점검에 띄운다.
- 실제 중개사에게 동의를 권하는 문자·알림은 보내지 않는다(시험 기간).

## 6. 정할 것
1. 고시 원문 대조를 누가 할지. 법률 자문을 받을지, 국가법령정보센터 원문 확인으로 끝낼지.
2. 등록번호로 귀속한 광고(`attribution='region'`)를 2차에 넣을지.
3. 관리비가 선택인 유형(상가·사무실 등)도 콕집에서는 입력을 권할지. 권장: 선택 입력, 있으면 표시.
4. 0단계부터 착수할지.
